# SOC Dashboard

A working Security Operations Center dashboard with a dark navy and orange UI.
It simulates attacks, detects them with rules, scores risk, and shows alerts live.

> Demo and learning tool. All events are synthetic. It does not monitor real systems or touch any network.

## Features
- **Dashboard:** live counters, 24-hour event heatmap, activity charts, security score, recent incidents, attack simulator
- **Alerts:** filter by severity or text, open a row for MITRE ID, threat intel, risk breakdown, evidence and recommended response, resolve or reopen, export CSV
- **Incidents:** escalate an alert to an incident (INC-1001, ...), set status (Open, Investigating, Resolved), assign an analyst, add investigation notes
- **Threat Analysis:** IP reputation lookup and 6 detection rules you can switch on and off
- **Event Logs:** searchable stream of every normalised event
- **Assets:** inventory with criticality. A Critical asset raises the risk score of alerts on it and shows open alerts per asset
- **Account and Team:** change your password, admins add and remove users
- **Audit Log:** who did what and when (logins, status changes, user changes), admin only
- **Security:** bcrypt passwords, sessions, lockout after 5 failed logins, role-based access, Helmet headers, authenticated Socket.IO
- **Live Events:** continuously updating stream with severity, source and destination IPs, asset and event type. Search, filter, sort, paginate, pause and resume (events keep arriving while paused), clear view
- **Time ranges:** 15 minutes, 1 hour, 24 hours or 7 days on the dashboard, click a rule label on the chart to drill into its alerts
- **Alert workflow:** acknowledge, resolve, escalate to an incident, with indicators of compromise and a timeline per alert
- **Live status strip:** connection state (Live, Reconnecting, Offline), data freshness, stale-data warning, server uptime
- **Interface:** light and dark themes, collapsible sidebar, skeleton loading, animated counters and charts, critical-alert banner, reduced-motion support. Theme, sidebar, range and severity filter are remembered
- **Simulated data is labelled:** every event in this build is generated by the built-in simulator and the UI says so. Set `AMBIENT=off` to stop the background traffic

- Explainable risk score 0-100 (severity + repeats + malicious IP + critical asset)

## Roles

| Role | Can do |
|---|---|
| ADMIN | Everything, including users, assets removal, rule toggles, audit log |
| ANALYST | Run simulator, resolve alerts, manage incidents, add assets |
| VIEWER | Read-only access to dashboards, alerts, incidents, logs and assets |

Create analyst and viewer accounts in **Account & Team**.

## Run locally

Needs Node.js 18 or newer (https://nodejs.org). Nothing else to install: no database server, no native builds.

```bash
npm install
cp .env.example .env     # on Windows: copy .env.example .env
npm start
```

Open http://localhost:3000 and sign in with `admin` / `admin123`.
Click the buttons in **Attack Simulator** and watch the dashboard update with a toast.

Run the tests: `npm test`

## Run with Docker

```bash
docker compose up -d
```
Open http://localhost:3000. Data is kept in the `soc-data` volume.

## Deploy globally (public link)

This app needs a Node server, so GitHub Pages will not work. Use one of these:

**Render (free)**
1. Sign in at https://render.com with GitHub.
2. **New, Blueprint**, choose your repo (it reads `render.yaml`).
3. When asked, set `ADMIN_PASSWORD` to a strong password.
4. Your link will look like `https://soc-dashboard.onrender.com`.
Free instances sleep when idle (first load is slow) and their disk is wiped on redeploy. The demo data and admin account are recreated automatically. For permanent data, add a Render Disk mounted at `/app/data`, or set `DATA_DIR` to its path.

**Railway / Fly.io:** connect the repo, start command `npm start`, set the same variables, and mount a volume at `/app/data`.

**Your own server (VPS):**
```bash
npm install && npm install -g pm2
SESSION_SECRET=your-long-random-string ADMIN_PASSWORD=your-password pm2 start server.js --name soc-dashboard
pm2 save && pm2 startup
```
Put nginx or Caddy in front for HTTPS.

## Configuration

| Variable | Purpose |
|---|---|
| `PORT` | Server port (default 3000) |
| `SESSION_SECRET` | **Change this.** Signs session cookies |
| `ADMIN_USERNAME` / `ADMIN_PASSWORD` | Admin account created on first start |
| `AMBIENT` | `off` stops the simulated background events (default `on`) |
| `DATA_DIR` | Where `db.json` is stored (default `./data`) |

Change the admin password by deleting `data/db.json` (this resets all data) and restarting with a new `ADMIN_PASSWORD`.

## Known limitations
- Data is stored in a JSON file, which is fine for a demo but not for heavy use. Swap in SQLite or PostgreSQL for production.
- Threat intel uses a built-in demo list, not VirusTotal or AbuseIPDB.
- Sessions are kept in memory, so everyone is signed out when the server restarts.
- No CSRF tokens or strict CSP yet.
- The default admin password is `admin123`. Set `ADMIN_PASSWORD` before the first start, or change it in Account & Team right after signing in.
