Security design

Boundaries are part of the design.

The project documents a set of application protections and one known session limitation. Review the implementation and deployment configuration before using it with sensitive data.

Password storage

Passwords are hashed with bcrypt at cost 12. Five failed login attempts trigger a 15 minute account lockout. First login requires a password change.

Request protections

State-changing requests use a session-bound CSRF token with constant-time comparison. Helmet sets a strict Content Security Policy. The app avoids inline scripts.

Roles and sessions

ADMIN, ANALYST, and VIEWER roles gate access. Session cookies are httpOnly and sameSite, with secure cookies in production. Socket.IO requires a logged-in session.

AI boundary

The optional analyst receives structured alert text and returns text. The chatbot can select from a fixed read-only function allow-list. AI-written SQL is not executed.

Threat intelligence

When an AbuseIPDB key is configured, the service checks public source IP addresses. Lookups are cached for one hour with a five second timeout. Without the key, a local list is used.

Known session limitation

A disabled user's existing session remains valid until that session expires. The documented session lifetime is eight hours.
